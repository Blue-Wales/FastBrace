## 编码与修改原则

本文档统一约束 AI 编程工具的实现方式。机械化格式、lint、类型和测试规则以
`pyproject.toml` 和 `Makefile` 为准。

### 实现前明确边界

1. 先确认需求、现有实现、影响范围和验收方式，再修改代码。
2. 不隐藏假设和取舍。多种解释会改变业务结果时，先列出差异并确认。
3. 能从需求、测试或相邻模块安全推断时，使用最保守的解释继续实现。

### 保持简单

1. 用满足当前需求的最少代码完成任务，不预先添加未要求的灵活性。
2. 一次性逻辑不抽象为新框架；已有通用实现时优先复用。
3. 函数保持单一职责，避免嵌套函数和函数内导入。
4. 名称应表达完整业务含义，不使用无法望文生义的缩写。

### 精准修改

1. 每一行改动都应可追溯到当前需求、修复的缺陷或由本次改动产生的清理。
2. 保留用户已有改动，不顺手重构无关代码。
3. 删除本次改动产生的无用 import、变量和函数。清理历史死代码时，必须先完成全仓引用检索并确认不存在动态加载路径。
4. 异常日志在能处理或增加诊断上下文的边界记录，避免每层重复打印；禁止记录密码、token 和密钥。

### 收尾校验

1. 先运行最小相关测试，再按改动范围扩大验证。
2. 完成前运行 `make agent-finish`；业务逻辑、API 或公共层变更同时运行 `make test`。
3. 不为通过 lint 而改变业务语义。
