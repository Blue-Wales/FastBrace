# Domain Entity Design Guide

This document describes the entity definition, base class capabilities, and writing conventions of `domain/entity/`.



## Entity Overview

Entities are domain objects that have an **identity** (ID) and are **mutable**. Criteria:

- The object has its own ID and the ID never changes during its lifecycle → Entity;
- The object has no ID, equality is by value, and it is immutable → Value object (see the [Value Object guide](domain-value-object)).

Entities carry **their own state and behavior**: for example, `UserEntity.add_attachments()` binds attachments. Keeping behavior and data together avoids the anemic domain model.



## Entity Base Class

`Entity` in `domain/entity/base.py` is the base class of all entities:

```python
class Entity(BaseModel):
    """Mutable entity base class"""

    entity_id: int = Field(default_factory=SnowflakeIDGenerator())
```

- `entity_id`: auto-generated by the snowflake algorithm;
- `validate_assignment = True`: validates types on attribute assignment;
- Attachment capabilities: `add_attachments` / `get_file_vo_list` / `get_file_vo_empty_list`, uniformly handling file fields such as avatars and photos, corresponding to the `FileType` enum.



## Existing Entities

| File                            | Entity                                          | Description                                                             |
| ------------------------------- | ----------------------------------------------- | ----------------------------------------------------------------------- |
| `entity/user.py`                | `UserEntity`                                    | User attributes, role/attachment assembly, admin protection             |
| `entity/role.py`                | `RoleEntity`                                    | Role attributes, closure tree, pre-delete validation (admin/sub-roles)  |
| `entity/permission_resource.py` | `PermissionTreeNode` / `DetailedPermissionNode` | Permission tree nodes, used by the permission service to assemble coarse/fine-grained permissions |



## Writing Conventions

- Inherit from `Entity`; declare fields with `Field(title="...")` and provide `default`/`default_factory` for nullable fields;
- Class docstrings use a short one-sentence description (e.g., "Role domain entity");



## Flow for Adding a New Entity

1. In `domain/entity/{module}.py`, inherit from `Entity` and define fields and behavior;
1. If the entity has file-type fields, name them per the `FileType` enum and create the corresponding table in `infrastructure/models/`;
1. Add the repository contract and implementation under `domain/repo/interfaces/` and `domain/repo/` in sync.
