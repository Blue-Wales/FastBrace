# 为什么选择FastBrace



## 背景


AI时代，构建产品的速度和效率大幅提升，选择一个好的**AI基座/脚手架**去构建产品能够事半功倍，同时大大降低开发、协作和后续维护成本，因此，我期望存在一个**架构清晰、轻量级、高性能**的AI基座/脚手架，能够让团队或个人开发者在此基础上减少重复搭建轮子的情况，并能在使用ai工具时大幅降低使用成本，更加专注于具体业务场景的实现。理想化的**AI基座/脚手架**至少需要以下几点：

1. 能够适配中小企业团队、个人独立开发者开发，降低后续维护成本、减少技术债返工情况
2. 能够统一各种规范和流程、提高ai开发时缓存命中率、大大降低开发成本
3. 具有完整的cicd、日志监控、工程规范，降低人工审查与线上风险
4. 轻量级、高性能，小步快跑，快速开发、快速上线验证
5. 高内聚、低耦合，专注于后台服务，降低与各种前端框架的耦合




## 调研分析



在深入调研分析市面上优秀的开源框架（诸如官方full-stack-fastapi-template以及FastAPI-template、fastapi-react、FastAPI-boilerplate）以后，没有找到对应符合理想化的**AI基座/脚手架**的框架，于是我结合多年企业级开发经验，开源了 FastBrace，并附带一个与优秀的开源框架full-stack-fastapi-template对比信息。以下是**FastBrace**与**full-stack-fastapi-template**模板的核心差异：



<div class="fh-compare">

| 对比维度       | FastBrace                                          | full-stack-fastapi-template                  |
| :------------: | :--------------------------------------------------: | :------------------------------------------: |
| 生态       | 中文文档 + 实战项目，贴合国内开发者习惯           | 英文生态，面向全球开发者                 |
| 迭代节奏 | 持续跟进最新技术并落地，活跃迭代                | FastAPI 官方出品，维护活跃、社区大           |
| 技术栈 | uv + Skill + FastAPI，纯后台脚手架 | React + FastAPI + Docker + Celery 全栈 |
| 学习成本       | 低：纯后台脚手架，专注后端     | 较高：需同时掌握前后端与容器编排         |
| 新手友好       | 非常适合：中文文档 + 实战项目               | 一般：全栈复杂度高，且文档为英文             |
| 文档体系       | 完整中英文文档，覆盖架构、功能、工程化与实战        | 官方文档完善（英文）                         |
| 实战价值       | 内置实战项目，可用于学习 Python、FastAPI、AI 应用开发 | 以模板为主，实战内容较少                     |

</div>

> [!TIP]
>
> FastBrace 更适合**中小企业团队、个人独立开发者**以及**追求轻量高效**的开发者。若你更看重国际化生态与官方背书，full-stack-fastapi-template 是更稳妥的选择。
