# 领域层设计指南

本文档说明 `domain/` 层的目录结构、各个子目录的适用场景等



## 分层定位

`domain/` 是 DDD 的核心层，承载业务规则与领域模型



## 目录职责

```text
domain/
├── aggregate_root/     # 聚合根：以聚合为边界的强一致入口
├── entity/             # 领域实体：有身份标识、可变的领域对象
├── events/             # 领域事件：异步任务事件在此定义
├── repo/               # 仓储：数据库操作的实现与接口契约
│   └── interfaces/     # 仓储抽象接口
├── service/            # 领域服务：跨领域协调、三方调用、复杂计算
│   └── interfaces/     # 领域抽象接口
└── value_object/       # 值对象：无身份、不可变的描述性对象
```



## 领域事件（events）

**什么情况用**：当业务操作成功后需要通过异步任务处理时，在此定义

​	常见场景： 发送通知、如发邮件、写日志、同步缓存等，发布领域事件，由 `event_handlers/` 异步消费，避免在事务内直接调用副作用逻辑。
